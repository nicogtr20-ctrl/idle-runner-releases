# ZERO410 — Automatic checkpoint must not abort genuine original-GRU3 motor learning

**28 October 2026. Experimental branch only, no APK/OTA.** Original user S21 GRU3 (33,312 past decisions, 512 cortical weights, 64 slow states, 194 physical senses and all 12 save slots) remains exactly the same binary V356/CRC. The V406/V407 original ≥10k test rule is mandatory; never use a 2k-only green trial as behavioral acceptance.

## Confirmed source defects

Original `GameActivity.Lab.onDraw` performs periodic scene save on `System.nanoTime()` every 12 seconds of REAL render wall clock. `saveScene()` unconditionally called `brain3.interrupt()`, even when a genuine neural motor decision was still active, discarding legitimate partial learning evidence. Thus adding instrumentation/logging or varying emulator/phone graphics throughput changes *which original motor decisions get censored* and can cause uncontrolled divergences between otherwise equivalent simulations. Explicit onPause/save remains intentionally interrupting and crash-safe, but autonomously scheduled save must not change the training dataset on wall-clock timing.

**Fix 1:** `GameActivity.originalV410MayAutoCheckpoint(simulationRunning,now,lastSave,brain3.pending())` requires wall-clock timer elapsed AND natural neural decision boundary. Timer isn't advanced while pending; the next completed decision gets saved. Uses `now-lastSave` to avoid signed-long wrap. Never interrupts a true on-going action just because UI reaches its 12-second checkpoint slot.

**Fix 2:** original `saveScene()` unconditionally called `brain3.interrupt()` even for completed decisions. Its V400/V401 implementation *always discards* the last completed `priorProbeV400`/local delayed eligibility trace before checking if neural `pending` is true. Thus even after deferring save to a decision boundary, a save lost the already-completed motor probe's valid one-step delayed evidence. V410 only calls `interrupt()` when a real `brain3.pending()` partial action exists; it now retains completed trace across ordinary mid-session autosaves, while saving unchanged original CRC/brain weights. On explicit onPause/suspend, `interrupt()` is still called before saving, so no unexecuted action can receive credit after process restore.

Both fixes change ONLY training data censoring at autosave, not the original GRU choice, MotorIntent, voluntary muscle commands, membrane traction, energy reward, physical hazards, user vision, memory persistence, named slots or 3.0 ownership. More reproducible tests are a benefit but NOT a guaranteed recovery of zero's 33k-trained EAST movement. Some simulator non-determinism remains from environmental physics timing, 0/100 energy handling and genuine gradient noise.
