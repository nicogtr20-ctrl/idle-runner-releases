## Confirmed architecture/learning findings
1. CRITICAL. `GameActivity` calls `OnlineBodyLearning.weights` and `OnlineBodyLearning.observe` for original `MotorBrain`/`ContactLearning`/`Morphology` weights on *every* observed interval. Under `useSymbiote`, the actual step is `symMatter.step(...,symMotor.commands(),slice)`, bypassing those candidates. Thus legacy candidate scores or accepted mutations are not causally tied to executed motors. Old bank mutation/selection and counters may be spurious. Gate these evaluations by which actuator is physically executed; do not delete prior archives or wipe trained weights.
2. CRITICAL. `SensorimotorMind.contactOutcome` updates four independent value models (`BodyProprioception`, `DistributedBodySense`, `LocalImpedanceSense`, `FluidInteroceptionV1`) immediately during action, before `diagnostics.shouldHoldout()` is drawn at decision boundary. Their `actualEnergy` methods change weights unconditionally when pending, even for heldout intervals. This contaminates validation-only outcomes. A redesign must determine split at action start and route actual outcomes exactly once; separate heldout predictor tests and value learning. Audit similar immediate hooks in temporal, navigation, causal and object models rather than merely patching four names.
3. HIGH. `BodyProprioception.sense` channel 2 in each 8-sector window is populated from `skin.extension[i]` (commanded target), not achieved physical extension. `SymbioteMatterV1.step` sets it before constraints and actual collision. A fixture modifying only the request changes "body" sensation while tissue remains still. Distinguish efference copy vs realized body geometry, preserve old schema via migration or calibrated transition.
4. MEDIUM/HIGH experiment validity. `WorldPlacement.free` checks only `item.x/y` versus a fixed origin with clearance `radius+68`. Protruding skin can overlap a freshly spawned object. This makes naive positive pickups ambiguous and can create surprise contacts, though actual pickup still uses physical material. Spawn code does not receive the 96-site membrane.
5. MEDIUM. `SymbioteMatterV1.work` is lifetime cumulative and `body.totalWork+=work*dt` double-integrates it; the aggregate increases after all commands are zero. The current metabolic debit uses `freshWork` correctly, so *do not* claim fuel debit is wrong; the body work counter is wrong and can mislead diagnostics or any old fitness mechanism reading it.
6. MEDIUM. `GameActivity.load()` constructs a new `GripContactObserver` then unconditionally deletes its separate `SharedPreferences` report, while `saveGripObserver` persists it and `TelemetryGitHub` exports it. This loses the previous grip flight report at app restart, with no recovery shown. Observer has no restore path.
7. REVIEW. `SensorimotorMind.contactOutcome` directly receives `object.signature` on physical pickup. Navigation receives this as `visuallyObservedSignature` before comparing actual visible frequencies (though an observed `sightAtTouch` snapshot is captured). Verify whether contact is intended to reveal wavelength through taste/touch; otherwise hidden spectral identity may leak from the environment oracle.
8. REVIEW. Some contact-derived `actualEnergy` hooks in temporal, causal, object and navigation modules update internal statistics immediately; verify all have train/heldout separation and avoid double credit with subsequent `consequence`.
